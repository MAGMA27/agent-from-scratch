# 工具系统
工具系统的细节很多，最基本架构是工具定义（按照格式定义工具）、工具发现（自动发现和加载工具）与工具注册（按照格式注册工具，方便tool call以及运行），需要借助参数 schema 体系做封装抽象。此外，还需要做变量的类型检查，危险操作检查等。

工具系统真正给 agent 按上了“器官”，让它拥有在电脑中按照其意志读写的能力。

## 整体架构
```txt
            ┌──────────────────────────────┐
            │          Tool (ABC)          │  ← 工具基类，定义契约
            ├──────────────────────────────┤
            │  Schema (ABC)                │  ← 参数 Schema 体系
            │   ├── StringSchema           │
            │   ├── IntegerSchema          │
            │   ├── NumberSchema           │
            │   ├── BooleanSchema          │
            │   ├── ArraySchema            │
            │   └── ObjectSchema           │
            └──────────────────────────────┘

            ┌──────────────────────────────┐
            │       ToolLoader             │  ← 自动发现 + 加载
            ├──────────────────────────────┤
            │     ToolRegistry             │  ← 运行时注册 + 执行
            └──────────────────────────────┘
```

### 工具定义

用抽象基类的方法将工具名、工具描述、工具参数、工具类型、输出格式等功能集成在工具内部，并使用装饰器工厂以及 schema 语法糖，让工具代码更具可读性。同时要内部做参数校验，增强可用性。

在危险操作时还需要及时拦截、询问或者直接设定访问边界，给工具安装上“护具”。

### 工具自动加载

nanobot 不仅定义了内置工具，还可以在 `pyproject.toml` 中添加了第三方工具的 `entry-points`，让第三方工具也可以接入nanobot。这个过程在 `AgentLoop` 启动前加载一次，除了 MCP 外不会热加载。Python 的模块导入有副作用、有状态，没有可靠的热重载机制（importlib.reload 只能刷新单个模块，处理不了跨模块依赖和类重新注册的边界情况）。所以这部分只做一次。此外，工具一般不会频繁改变，不值得每一轮都去支付发现的花销。

MCP 工具不是代码。它们是远程进程暴露的能力。配置文件里加一行 my_server: { command: "npx", ... } 不需要改动任何 Python 模块。reload 的逻辑是：关连接、开连接、注册/取消注册，这些操作都是安全的。

### 运行时注册

通过 `ToolRegistry` 管理工具，返回给 LLM 的 schema 列表，并可以一站式调用：校验 → 执行 → 异常处理。
